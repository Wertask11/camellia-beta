# 店舗の掲載管理（2026-11-11）

独立入口 `/?open=place-operator` を用意。利用者のCheck・女性向けプロフィール・私的記録のstoreを起動せず、既存LINE／Googleで認証し、サーバーの担当権限を照合する。LINEは既存のoriginルートへ戻る。用途だけの10分hintを端末に保存し、OAuthのstate・nonce検証は従来の認証処理に任せる。新しいcallback URLは不要。

担当scopeの割当がない利用者は管理画面を開けない。スタッフは自店の下書き追加／編集、審査依頼、停止、無料掲載同意、集計を利用できる。運営だけが4つの確認と証跡を記入して公開できる。証跡は公開・店舗側レスポンスへ出さない。公開flagがOFFでも管理APIは本人の認証・権限を確認して準備に使える。

編集はupdatedAt照合、新規は同名slugがまだ存在しないことを確認し、古い編集による上書きを拒否。編集欄の入力は失敗時に残す。保存はdraftへ戻るため、公開中の内容を変更したら再審査が必要。slugは後から変えず、新しいURLが必要なら運営と調整する。

管理プレビューの閲覧・外部リンクの確認を利用者の成果集計へ加算しない。人数・来店・予約成立などの成果を作らない。写真と全外部URLは既存server validatorで検証。新しいページは掲載候補を用意できる入口であり、架空店舗の公開や本番権限付与ではない。

担当者の登録：この入口で本人がLINE／Googleを使用する→運営がFirebase Auth側で担当者を確認→データ保護差分のscope CLIをdry-run→承認後だけ付与。解除はslug `-`。無効化／削除済み担当者も解除できる。global operator claimを一般店舗へ渡さない。公開実績は実店舗受入後に別判定する。

ブラウザ5幅で専用入口→合成Google→下書き→審査依頼、スタッフに公開ボタンが出ないこと、利用者の個人storageが生成・変更されないこと、公開成果イベントを出さないことを確認。これは実LINE／Googleや実店舗掲載の証明ではない。
