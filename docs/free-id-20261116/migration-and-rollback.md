# データ保護・移行・復旧

## データの境界

- 既存 `camellia-prototype-v3` と、登録前の `camellia-free-device-v1` は別。既存v3/v4 readerとlazy v4保存を維持。全Firestore recordの一括migrationはしない。
- Freeはブラウザへ継続保存。ブラウザ削除・プライベートモード・容量不足・共有端末は制約。保存できない場合は原本/書込み提案の控えを保護して停止し、成功表示しない。localStorageの比較/書込みは原子的ではないため各タブの提案控えも保持する。
- 移行は本人が入口を選び、認証した現在UIDへ固定し、対象件数を確認した後に追加。メール一致を根拠に別IDを合併しない。既存IDのメール追加はFirebase linkで同じUIDを保つ。
- 当前IDの設定・tombstone・有料/試用権利を保護。過去の操作イベントを再送せず、JST同日のFortuneを重複作成しない。

## 途中失敗の復旧

`camellia-free-transfer-v1` と `camellia-free-transfer-source:{nonce}` は同じUIDの復旧用。適用中/適用済みは10分経過だけで消さない。再ログインを禁止せず、認証UIDが一致する場合だけ復旧を続けられる。別UIDでは原本を取り込めない。

取込み前に原本を控えへ移して、ログアウト後の新Free画面へ移行済み内容を出さない。ローカル取込みだけで完了とせず、同じUIDのFirestore root→imports→rootを読み、revisionが安定し期待する各recordが同等以上で含まれることを確認する。確認できなければ控えを残し、手動再試行。保存失敗・UID変更時に原本を破棄しない。

完了後も、並行タブで保護した控えは未確認の変更を含む場合があるので勝手に消さない。ローカルの所有関係 `camellia-free-adopted-sources-v1:{uid}` で現在IDだけがその控えを書き出し/削除できるようにする。個人記録削除ではそのIDへ移した控えも削除し、別IDの控えは対象外。ダウンロード済みのファイルは本人が削除する。

## ロールバック

1. 先に端末の個人記録を書き出し、必要な原本控えと同期revisionを確認。全件削除や旧ファイルの上書きはしない。
2. UI切替 `VITE_FREE_BASIC_USAGE=off` による旧入口復帰は次回buildで可能。**実際の設定変更は運営承認後**。Free保存領域は消さない。メールIDは旧入口にも任意ボタンがあり、メールcallbackの処理を維持する。
3. 端末記録・移行控え・メールIDに対応した今回のコードを残し、画面を切り戻す。メールSDK/新保存領域を知らない古いcommitへ戻すと、記録が残っていても表示/引継ぎができないため互換ロールバックと呼ばない。
4. v4保護済みの基盤 #68〜#73 とCAS/削除lock/同期原本保護を外さない。Firebaseのverified email条件を弱めない。サーバー/Rulesの差分は別途照合し、SchoolPark共用のRulesを丸ごと上書きしない。
5. 新Free会話だけの緊急停止はprotected `config/free_chat.enabled=false`。既存認証済みFree会話を一括停止する必要はない。設定変更・公開判断は今回実行していない。

Firebaseの共有Authユーザー自体をMyの個人記録削除で消さない。Circle本文、共有Auth、契約、監査等の削除は従来Terms/Privacyと運営申請に従う。不要な他サービス削除を行わない。
