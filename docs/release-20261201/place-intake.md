# 店舗の掲載相談と担当割当（2026-11-19）

実店舗・掲載許可・写真許可は未取得。以下は実装とローカル合成検証であり、実店舗の公開実績ではない。

## 入口と運用

`/place-partners.html` は基本掲載無料・運営審査・写真許諾の必要性を案内し、既存の `/?open=place-operator` へ接続する。既存LINE/Google/メール確認を利用し、新しいOAuth callbackを要求しない。店舗担当者に消費者向けプロフィールやPlus権限を自動作成しない。

1. 運営が非公開設定 `config/place_application_intake` の enabled/approved/privacyReviewed/approvedBy/approvedAt と保持方針を承認し、サーバーの `CAMELLIA_PLACE_APPLICATIONS_ENABLED=true` を別途承認してから受付する。既定はOFF。コード変更だけで開始しない。
2. 保持設定 `config/retention.collections.place_applications` は `mode=closed_only` と承認済みの正の retentionMs、同 `place_application_audit` も承認済みの期間を必要とする。期間は未決定であり実環境へ設定していない。
3. 担当者本人が店舗情報と非公開連絡先を入力し、同意して申請する。フォームの入力途中を個人記録やlocalStorageへ保存しない。申請の再送は同じrequestIdを使い、二重作成を防ぐ。
4. 運営は既存 `camelliaPlaceOperator` または `camelliaAdmin` claimをサーバーで確認した審査画面で、受付→確認中へ進める。新規claimをこの作業で付与しない。
5. 店舗の実在・担当者との関係を運営が確認し、URL用slugを指定する。承認操作は **非公開draftと当該slugだけの担当scope** を同一トランザクションで作成する。連絡先・運営への補足を公開draftへコピーしない。
6. 店舗担当者が既存Place管理機能で下書き・写真・許諾証跡を整え、運営の既存公開審査を受ける。申請承認自体は掲載・提携・広告・写真許諾を成立させない。
7. 担当変更時は申請画面から対象店舗だけのscopeを解除する。他店舗のscopeは保持する。認証アカウントの削除・UID再利用の前にもscopeを解除する（既存scope全般のUID再利用時自動失効を保証する機能ではない）。
8. 進行中は期限で削除しない。担当解除後の承認済み案件は運営が保管終了を選べる。見送り・取り下げ・保管終了だけを `closedAt + 承認期間` による削除候補にする。

## 私的データ・削除

申請者は自分の申請、運営は権限内の審査一覧のみ閲覧できる。認証IDの作成時刻も照合し、再作成された同一UIDから以前の申請を読ませない。申請からCircle参加資格や有料資格を作らない。停止アカウントの新規申請・運営操作は拒否し、本人の取り下げは残す。

本人が未割当の申請を取り下げると本文・連絡先を直ちに除去する。割当済みの削除は運営へ相談し、権限解除と保持判断を分ける。操作監査は本文・メールを含めない。Myの個人記録export/resetとは別の事業記録であることをUI/Privacyに明示した。サーバー事業記録の開示・消去依頼は運営が本人確認して対応する。

期限による物理削除は、既存の許可済みコレクション制限・dry-run・対象digest承認・再照合・監査を備えた削除処理へ接続した。`expiresAt`を置いただけで削除済みとは扱わない。稼働中の申請やPlace本体はこの削除で除去しない。TTL/定期ジョブは本番設定・起動していない。
