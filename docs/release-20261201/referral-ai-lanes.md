# 無料30回と紹介専用枠の分離

最終監査で、新規紹介のPlus権利も通常会話の上限を外してしまう組み合わせを検出した。紹介公開前に修正し、新規紹介trialの通常レーンにも無料の日30回を適用する。既存の正規paid/operator Plusに、未決定の新しい回数上限を無断適用しない。

紹介専用の拡張は、通常30回を使い切った後、本人が「紹介体験の会話枠で続ける」を選んだ再試行だけ。モデルや文脈を勝手に切り替えず、元の送信/会話/話し方へ戻す。自動で専用枠を消費しない。次の日は再び通常枠を優先する。匿名Free APIでは専用レーンを拒否する。

UIへ渡すのは版付きの可否だけで、成立済みtrial、専用枠/価格/期限/使用状態、日次利用をサーバーで確認する。可否は予約の保証ではない。実要求時にもう一度認可し、回数/入力/出力-thinking/費用を同一トランザクションで予約する。未設定・不明原価・失効・枠不足をprovider成功や高性能モデルと扱わず、trial_limitedとして利用者へ案内する。通常のprovider503等は従来の障害表示のまま。

紹介は既定OFF。具体的な専用枠やPlus会話方針を決定したものではない。サーバー設定・公開/課金・新規trial付与を開始していない。

回帰: 正規Plusの旧挙動維持、新規trialの30回厳守、JST reset、通常枠より先の専用要求拒否、claim/価格と使用状態の可否、laneの明示転送、provider/枠エラーの分離。Chromiumの375/390/412/768/1280で、通常枠エラー→明示ボタン→同じmodel・元メッセージの再試行を確認。認証/枠/返答は合成、実Geminiや実trialではない。
